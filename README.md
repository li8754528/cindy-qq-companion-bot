# QQ 群伙伴 1.5.0

腾讯官方 QQ 群 @ 文字、图片或图文问题 → 当前正式版 Cindy 的指定本机伙伴 → reply_to_qq → 原群关联回复。无需运行开发版 Cindy。插件包含随包 Node 工作进程和腾讯官方 QQ SDK，不在运行时下载依赖。

启动自检和故障诊断显示在首页；机器人卡片分别显示运行、连接和暂停状态。删除按钮位于账号标题旁，可删除最后一个机器人。伙伴头像和名字合并为单选卡，切换后即时保存。

这是 [Cindy](https://github.com/makecindy/cindy) 的独立插件项目，当前版本 1.3.0，最低支持 Cindy 0.1.124，已核对该版本的任务创建、默认模型与伙伴投递接口。

## 功能

- 默认处理机器人已加入的所有群内 @，无需填写群 ID。
- 支持文字及 PNG/JPEG/WebP 图片提问，最多 4 张图片。
- 最多配置 4 个机器人，各自保存凭证并交给不同伙伴处理。
- 按机器人、群、发言人和伙伴记录近期问答，支持连续追问。
- 保存完整配置后自动连接，启动或连接进程中断后恢复；主动暂停会保留。
- 设置页显示伙伴名称、ID 和名称头像，支持窄屏及明暗主题。

## 从源码使用

1. 克隆仓库，在项目目录执行 `npm ci --ignore-scripts --no-audit --no-fund`、`npm run build` 和 `npm test`。
2. 在 Cindy 中让助手使用插件 Forge 的 `ghost_forge_pack` 打包此目录，生成 `.cindy` 文件，再通过 Cindy 的插件安装入口导入。也可以明确要求助手用 `ghost_forge_install` 安装当前源码目录。
3. 在插件设置填写自己的 QQ AppID、AppSecret，伙伴默认不选，问题会新建独立对话并使用系统辅助模型；也可选本机伙伴。补齐账号与凭证后保存会自动连接。

详细配置和限制见 [使用手册](manual/quick-start/MANUAL.md)。仓库包含运行文件 `main.js`、`node/worker.cjs` 与图标；`src/` 是源码，`tests/` 是回归测试。账号配置、保险库凭证、运行记录、依赖目录和本地安装包不随源码提交。

## 配置

见 manual/quick-start/MANUAL.md。每个机器人保存 AppID/AppSecret，可选择伙伴或保持不选，默认接收机器人已加入的所有群内 @，无需填写群 ID。最多 4 个机器人，可分别指定不同伙伴。任意 QQ 群是否可加入、测试及上线规则以 QQ 开放平台为准。

## 本地构建

Node 20 或以上：npm ci --ignore-scripts --no-audit --no-fund，然后 npm run build 与 npm test。打包通过 Cindy ghost_forge_pack；不要把 node_modules 作为运行时依赖。SDK 1.0.5 和 ws 许可见 THIRD-PARTY-NOTICES.txt。esbuild 为仅构建依赖。

## 权限与数据

插件需要常驻运行、随包 Node、保险库 AppSecret 的指定方法注入、指定伙伴投递和私有 fs。AppSecret 不进 /kv、广播频道、日志、状态文件或 Agent 工具结果。Node 为受信任原生代码，可联网；SDK 日志关闭，输出只含脱敏 JSON-RPC。

/kv 保存非秘密配置（schema 2 的 bots 列表），每个机器人使用独立的静态凭证槽和独立 connect 方法，当前宿主最多支持 4 条 secretBindings。第一个机器人沿用 qq_app_secret 及 bridge-state.json，原配置自动迁移，保持同来源更新时的凭证。其它机器人分别使用 qq_app_secret_2/3/4 与 bridge-state-bot2/3/4.json；不绕过宿主换源隔离。

状态文件保存问题状态、QQ 提供的发言人 openid，以及已确认回群的近期问答。openid 是 QQ 的接口标识，不是可反查的 QQ 号码；不跨机器人合并身份。追问按 AppID、沙箱环境、群、发言人和伙伴精确匹配，保存 7 天、最多 8 轮/12000 字符；每个机器人最多 80 个近期会话，超过时淘汰最旧记录。群内 @ 后发送“新话题”“重置对话”或 /reset 可重置本人的记录。插件界面可清空追问记录，伙伴原对话仍保留。失败或不确定的回复不进入追问上下文。

QQ 图片地址只短暂保留在 Node 进程内，下载字节分段交给宿主，不写入插件状态文件；追问记录包含图片相关的文字答复，不再次附带原图。需要重新看原图时须重新发送。插件只下载固定 QQ HTTPS 图片 CDN，不向图片请求附加凭证，限制大小并检查格式。图片进入伙伴消息后由 Cindy 媒体系统保存。停用保留数据，卸载按宿主行为删除插件私有数据。

打包校验和本地测试通过不代表 QQ 账号具备上线资格，也不代表真实群或所选 AI 已完成回复。已有安装实例的文字请求状态已验证为 replied；图片收发验证使用假宿主及假 QQ 图片响应，未主动发送真实 QQ 群图片或替用户发测试消息。真实图片识别与回群仍需由群成员测试。插件尚未发布到 Cindy 插件市场。

## 1.1.0 图片支持

群友在同一条消息里 @ 机器人并发送图片，可附带文字，也可仅发图片。支持 PNG/JPEG/WebP，每条最多 4 张，每张 5 MiB；GIF、视频和其它文件明确标记不支持，不静默只转交文字。下载地址过期、来源不支持、当前连接更换或宿主能力缺失时显示 IMAGE_* 状态，请发新的图片提问。排队的图片链接不会跨重连保留；已受理结果不确定时不重放。回群仍为不超过 1800 字符的单条文字。

## 1.2.0 多机器人与追问

新界面为机器人列表和独立账号、伙伴、状态。伙伴显示头像、名称和 ID；当前正式版公开 targets 接口只保证 id/label/detail，不提供原头像，因此默认使用名称首字头像；若未来接口带 HTTPS avatarUrl 则使用它。未读取宿主私人数据库或私有 IPC。追问上下文由插件精确筛选注入，伙伴仍使用既有 canonical 会话，这不是模型历史的强隔离机制；建议群答疑专用伙伴。

## 1.3.0 自动连接与恢复

保存完整 AppID 和加密凭证后默认启用并连接；不完整配置只保存草稿。伙伴可不选，默认新建独立对话。Cindy 启动后连接已启用的机器人，并自检后台连接。连接进程停止或崩溃时先探测当前连接：健康连接不重复断开，SDK 正在恢复时等待；确实失效时仅重建连接，按 10/20/40/60 秒退避。主动暂停保留；缺少凭证、权限或所选伙伴不可用时等待用户处理，不持续重试。恢复不会重放已发送或结果不确定的请求。

## 主动给群发消息

主人可在 Cindy 中要求“用机器人 1 给这个群发通知：……”。AI 先通过 `get_status` 确认机器人和已观察到的群，再调用 `send_group_message`，明确传入 `bot_id`、`group_openid`、`text` 与唯一 `request_key`。群 OpenID 是该机器人的事件标识，不是 QQ 群号；群尚未出现在状态里时，可先在群内 @ 对应机器人一次，或提供已核实的群 OpenID。

主动消息仅发送文字，最多 1800 字符，不需要原消息、不引用旧消息、不创建问答会话。QQ 群转交的问答任务不能调用主动发送工具。机器人必须已连接并加入目标群，QQ 平台须允许主动发送；权限和频控拒绝会返回错误码，不自动重试。

`request_key` 由 AI 为每次新发送生成，相同编号与相同目标和内容七天内只发送一次；重复调用返回已有回执，不同目标或内容报冲突。独立的 `proactive-state.json` 只保存内容摘要和发送状态，不保存正文。插件重启、连接切换、网络中断或回执缺失时记为结果不确定，请检查原群，不要换编号重发。`get_status` 的 `proactiveMessages` 列出最近 24 条记录，成功回执包含实际机器人、AppID、环境、群和消息 ID。

主动发送记录仅向主人在 Cindy 中的任务展示，七天过期记录不再显示。发送前状态保存失败会阻止这一请求，恢复写入后可处理新的发送。若 QQ 已确认送达、仅回执保存失败，仍返回成功回执，附 `state_saved: false` 和提示；不要因此重发，重启后该记录可能显示为结果不确定。切换账号或 sandbox 期间会核对实际连接，避免通过旧环境发送并返回新环境回执。

官方接口：[发送群聊消息](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html)。当前文档主动频控：已认证机器人 60 条/分钟、未认证 30 条/分钟；每群 20 条/分钟、每天 1000 条，以 QQ 平台实际配额为准。
