# QQ 群伙伴：群项目与成员会话设计

仍需群内 @，无需 /talk。每个群配置 Cindy 项目和完整本机模型组合；不同机器人、AppID、环境、群、成员分别使用普通任务，不继承旧伙伴历史。

## 项目与模型

设置页用 targets.list(project) 展示真实可用项目，用 Cindy 统一选择器获取 {agentKind,providerId,model,effort,fastMode}。首条消息只调用一次 targets.send(project,route)，同时创建并受理输入；保存返回 taskId。后续用自有 tasks.get/setModel/send 复用任务，不为获取 runId 再投递首条消息。

新任务权限沿用主人在插件“模型与任务”中选择的动手权限，默认询问。已有任务沿用自己的权限，插件不自行提升。每群模型保持显式组合，来源或模型不可用时明确失败，不自动换供应商。

## 两小时续聊与队列

Host确认受理的有效 @ 或 QQ确认送达的最终答案才续期。重复、无效输入、队列拒绝和未确认发送不续期。两小时无有效互动后下次 @ 使用新任务。项目、模型、环境或成员改变时使用独立映射；旧迟到答案不会覆盖新映射。

1.6.2起只串行提交宿主输入，已受理请求等待最终答案期间不锁住机器人或成员。同成员复用已确认的taskId，输入交给宿主原生队列顺序处理；其他成员独立提交。旧受理结果不确定时轮换会话，并重新绑定尚未投递的本地输入，不重投旧请求。连接中断时最多十二条本地待投递；waiting不占容量。长时间等待仅作诊断，迟到回复资格保留。重启清除waiting的旧成员阻塞；旧queued未保存正文仍取消，需重新@。

## 最终答案

reply_to_qq只接受实际收到原问题的任务，模型只提供文本，机器人/环境/群/原消息从请求记录确定。所有年龄的最终答案都先回复原消息；可信明确平台拒绝后才主动发送同一答案一次。成功停止；网络、超时、5xx、未知/重复业务码或缺可靠消息回执均uncertain，不补发、不换键，不重复生成问题。

原请求单份持久记录管理被动及主动阶段。同步领取最终内容指纹，两份状态镜像写入并回读后才外发。重启遇到未终局发送意图标uncertain，不重放；镜像损坏、不一致或未知版本保留数据停发。双文件验证不等同硬件掉电保证。

## 引用与协议

官方依据：[发送群聊消息](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html)、[群@机器人事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/group_at_message_create.html)。

msg_id取事件d.id，属于被动关联。message_reference.message_id取message_scene.ext中的msg_idx，属于引用展示，不能互换。只投影非空引用索引和timestamp，不把raw/ext/auth_token传给模型。有索引才传引用，无则省略；不拼文本@冒充原生提醒。真实QQ客户端引用展示与真@提醒需独立验证。

## 升级与诊断

schema2→3保留机器人槽位、账号、环境、暂停与原保险库key，删除执行targetId。旧群需明确配置项目和模型，不猜路径；原Cindy任务及历史保留。旧请求和QQ来源拒绝信息用于防重，不重新派发旧问题。

同安装作用域内的schema迁移不等于跨来源账号继承。宿主先归档换源数据时，新插件不能读取另一个归档的凭证。升级边界与实际宿主回归见[升级保留](upgrade-preservation.md)。

get_status区分caller_scope与config_visibility。只有确认主人视图包含全局config；群来源只见自有任务请求，未核实来源不提供全局配置。空可见请求列表不能代表账号/凭证删除；未知来源仍禁止任意群主动发送。

## 验证与限制

单测覆盖作用域、两小时边界、源身份/权限拒绝、两阶段发送与崩溃/写失败/并发、防重及真实SDK本地HTTP字段。UI smoke使用生成main.js与设置页、Mock Host/QQ，验证窄屏与Light/Dark及选择/暂停/恢复行为。包由Forge校验；打包不安装。

普通任务和共享项目仍按Cindy正常权限工作，原生历史分离不声称OS沙箱。真实账号、模型、权限卡、QQ展示及手机/远程页面需要真实环境另行验证。接口按运行能力探测；不把其它源码版本或开发分支当作执行宿主证据。
